# NE S27: дополнения к заданию Discord-бота

Зафиксировано 12.09.2026. Это контракт будущей интеграции, а не заявление, что бот уже подключён. Сайт: https://ne-s27-zone.r9d8npjbr7.workers.dev

## Новые требования

1. **Два подтверждённых приглашённых участника = один купон.** Не три. Уникальный Discord ID приглашённого учитывается один раз за всё время. Выход и повторный вход не дают новую награду. Боты, самоприглашения, неатрибутированные вступления не засчитываются. Сохранять события, проверять условия присутствия, передавать подтверждение сайту. Сайт авторитетно считает и начисляет; бот не выдаёт вторую награду независимо.
2. **Кабинет менеджера на сайте**: создание кодов и обработка призов, без доступа к настройкам сайта, шансам, общим админским выдачам или назначению ролей. На живом сервере менеджеры задаются серверной переменной `MANAGER_DISCORD_IDS`; администраторы — `ADMIN_DISCORD_IDS`. Не доверять Discord-роли, ID или флагу из браузера. Тестовый менеджер `lab:manager` обслуживает только тестовые коды и заказы.
3. **Призовые коды**: 1–15 купонов за активацию; одна активация всего. **Коды сообщества**: 1–15 купонов, максимум N разных участников (обычно 100), один раз на участника. Создание до 15 отдельных кодов за операцию. Пустое поле = случайные 16 символов A–Z, a–z, 0–9 в формате `Ab3K-x7Mn-Pq9R-sT2v`. Пользовательский код допускает один символ, регистр важен, по краям убираются пробелы, применяется Unicode NFC. Своё значение создаётся по одному. Код можно отключить без удаления истории.
4. Источник истины кодов — база сайта. Бот не хранит вторую независимую таблицу лимитов. Не отправлять код публично автоматически. Выдача победителям — личное сообщение по явной команде менеджера; предусмотреть закрытые личные сообщения и выдачу менеджеру приватного результата. Генерация сайта сама никому ничего не отправляет.
5. **Счётчик участников**: при готовности бота, вступлении/выходе и периодически раз в 60 секунд отправлять актуальный `guild.memberCount` только нужного сервера. Debounce 5 секунд для массовых вступлений, периодический heartbeat даже без изменений. Сайт опрашивает своё API раз в минуту, показывает время обновления и устаревание через 3 минуты. Не имитировать онлайн случайными числами. Это количество участников, не статус онлайн.
6. **Призы и тикеты**: участник оформляет заказ на сайте и нажимает «Получить». Бот после подключения создаёт приватный тикет только для участника, менеджеров и бота. Привязать один тикет к `order_id`; при повторной доставке не создавать дубликат. Перед созданием проверить, что заказ ещё ожидает обработки, принадлежит пользователю и не возвращён. Уведомить нужного менеджера и участника внутри тикета. Статусы: pending → processing → fulfilled либо refunded; пользователь может отменить только pending с однократным возвратом жетонов. Не возвращать жетоны при обычном закрытии Discord-канала без команды и подтверждения серверного API.
7. **Профиль**: синхронизация username, display_name и avatar_url после привязки, при изменении профиля и периодическая сверка. Собственные украшения сайта, список желаний, сохранённые образы, карточки и баланс не затирать. Discord-пароль никогда не спрашивать. Нужна согласованная одноразовая привязка, не передача постоянного пароля через чат.
8. **Награды комплектов** по умолчанию выключены до решения администрации. Не выдавать придуманные награды. События и конкурсы на сайте имеют явно заданные условия и награду; проверка одной заявки не начисляет повторно при повторе события бота.

## Что уже доступно в API сайта

`POST /api/bot` принимает JSON с HMAC-подписью. Заголовки:
- `x-s27-timestamp`: Unix timestamp в секундах;
- `x-s27-signature`: hex HMAC-SHA256 от строки `${timestamp}.${rawBody}`;
- `Content-Type: application/json`.

Подписывать **точные байты JSON**, отправленные в запросе. Общий ключ `BOT_WEBHOOK_SECRET` хранится только в серверных секретах сайта и хостинга бота. Допустимое расхождение времени — 300 секунд.

Новая реализованная операция:
```json
{"action":"guild_stats","memberCount":847}
```
847 — только пример формата, не реальное число участников NE S27. Публичный `GET /api/guild-stats` возвращает `members`, `updatedAt`, `stale`; до подключения members=null.

Текущий сайт также имеет операции `ping`, `sync_member`, `create_link` и обработку приглашений; перед реализацией сверить полный актуальный `app/api/bot/route.ts` и `BOT_PROMPT.txt` из репозитория. Сейчас `create_link` выдаёт короткий код входа на сайт от бота, а не реализует обратную `/connect` привязку аккаунта сайта. Не заявлять, что это уже один и тот же протокол.

`/api/reward-codes` сейчас является **браузерным API с сессией**, не API токена бота:
- GET — менеджеру: список кодов и последние активации;
- POST action=create — менеджеру;
- POST action=disable — менеджеру;
- POST action=redeem — участнику, начисление атомарное.

Если нужны Discord-команды для создания/погашения кодов, сперва добавить отдельные подписанные операции сайта с проверкой actorDiscordId, прав и уникального requestId. Не пытаться использовать браузерные cookie или пароль менеджера в боте. Аналогично требуется реализовать подписанный протокол очереди заказов и подтверждения ticket_id: сейчас автоматической передачи тикетов ещё нет.

## Команды следующего этапа

- `/profile` — ссылка на профиль и актуальный баланс.
- `/invite` — индивидуальная отслеживаемая ссылка, прогресс до 2 участников.
- `/connect <code>` — после согласования обратной привязки с сайтом.
- `/codes create`, `/codes disable`, `/codes list` — только после добавления подписанного API; ответы приватные.
- `/prize status` — статус собственных заявок.
- Менеджерские действия в тикете: взять в работу, отметить выданным, вернуть жетоны; все решения проверяются сайтом и журналируются.

## Обязательные проверки

Одновременная активация последнего места общего кода двумя аккаунтами даёт награду только одному. Один аккаунт не получает её дважды. Выключенный/исчерпанный/чужой тестовый код не работает. Регистр и дефисы проверяются точно. Истёкшая и изменённая HMAC-подпись отвергаются. После перезапуска очереди восстанавливаются; повтор webhook не удваивает награду или тикет. Закрытые личные сообщения не приводят к потере кода. Бот имеет минимальные права, а не Administrator. Логи не содержат паролей, токенов, секретов и кодов привязки.

Хостинг бота — bot-hosting.net. Сделать конфигурацию окружения, журнал ошибок без секретов, повтор с задержкой для 429/5xx, корректное завершение и инструкцию запуска. Сам сайт, карточки, изображения и анимации в этом задании не создавать.
